# T1Vibe

在 Windows 上使用 google TV T1 遥控器操作 ChatGPT 桌面应用，支持官方听写、聚焦输入框、左侧导航和对话滚动。

目前只测试了 USB 接口，蓝牙未测试

## 按键

| 按键 | 功能 |
| --- | --- |
| 应用图标 / Apps | 进入对话浏览 |
| 语音 | 触发 Windows 听写 Win + H |
| 主页 | 左侧导航，优先当前高亮条目 |
| 上 / 下 | 左侧选择条目或滚动对话 |
| 确认 / Enter | 输入框发送；会话行打开；项目行新建聊天；对话浏览区回到输入框且不发送 |
| 返回 | ChatGPT 前台时聚焦输入框 |

返回、Apps、Home 仅在 ChatGPT 为前台时接管，其他应用中保持原始行为。上下和 OK 跟随实际焦点，鼠标切换区域后立即按新区域处理；左右和电源键保持原始行为。程序不会启动或唤出 ChatGPT，请手动切换到应用。

## 使用与兼容性

适用 Windows 10/11 x64、.NET Framework 4.8。双击构建后的 `dist/T1Vibe.exe`，右键托盘图标退出。无需旁置 DLL 或开发工具。

目标应用进程名为 `ChatGPT`，启动标识为 `OpenAI.Codex_2p2nqsd0c76g0!App`。其他发行版、界面语言和结构需重新验证。Win + H 须事先可用，输入麦克风由 Windows 设置决定。

语音信号不限制接收器 VID/PID；通过 Windows HID 描述解析 Consumer Control 的 Voice Command（Usage `0x00CF`），支持不同 Report ID、按键数组及位图报告。描述不可用时兼容原有 `02-CF-00` 格式；同时支持 Windows 听写切换媒体命令（APPCOMMAND `43`）。HID 长按只触发一次，松开后可再次触发；插拔接收器后会重新读取描述。主页和返回原始 HID 按 `VID_1915/PID_1025` 过滤。侧栏只处理可见条目，不自动滚动。

## 本地和 UU 远程使用

两台电脑都运行同一个 `T1Vibe.exe`，不加参数。先从两端托盘退出旧版或实验版，再启动新版。无需选择本地、转发或接收模式。

语音键在所有应用中直接触发 Win+H，不改变输入焦点。本机 UU 远程画面在前台时，Win+H 由 UU 转发给远端 Windows；其他导航键保留原始事件，由 UU 送至远端，再由远端 T1Vibe 根据 ChatGPT 前台和实际焦点处理。离开 UU 后自动恢复本机使用。

2026-11-07 已由用户实测：本地记事本收到语音键后系统听写正常弹出；UU 中远端记事本也正常弹出，远端 T1Vibe 原始语音键触发次数为 0，支持直接转发 Win+H 的方案。此结果限于该次 UU 配置。其他导航键、界面焦点和滚动仍需真实设备验收。

语音来源与音频链路沿用现有 Windows/UU 配置。新版本正常使用不依赖 F9。旧的 `--voice-relay`、`--uu-receiver` 启动参数仅保留兼容用途，请勿用于这套统一方案。直接 Win+H 实验仍可用 `--voice-direct-experiment` 启动。

## 构建与测试

在 Windows PowerShell 中运行（首次构建会自动下载并校验 Zig 0.13.0）：

```powershell
./build.ps1
```

脚本使用 Windows .NET Framework C# 编译器和 Zig，只生成最终程序 `dist/T1Vibe.exe`（中间编译文件放在 `build/`）。重新构建前先退出正在运行的程序。可用 `-OutputDirectory` 指定其他输出目录，此时中间编译文件位于该目录的 `build/` 子目录。

如需同时运行自动测试，执行 `./build.ps1 -Test`。首次构建会从 Zig 官网下载到脚本所在目录的 `tools/ziglang/`，需要网络连接；如已安装 Zig，可用 `-Zig` 指定编译器路径。

语音键无反应时，先从托盘退出程序，再运行 `./dist/T1Vibe.exe --diagnose-voice`。按一次语音键和一次正常工作的遥控器键，随后退出程序，查看 `%TEMP%\T1Vibe-voice-hid.log`。诊断模式会记录原始 Consumer Control 报告、媒体命令和键盘虚拟键值；期间不要输入密码，排查后可删除日志。

如需对比其他功能键和语音键是否传到本机，运行独立的 `dist/T1VibeKeyCheck.exe`（用 `./build-key-check.ps1 -Test` 构建，无需 Zig）。先退出 T1Vibe 主程序，再在实际远程桌面双击验证程序，点击“开始逐键验证”，按提示依次短按应用图标、主页、上、下、确认、返回、语音。每项 8 秒，语音 12 秒；结束后可选中一项重测。程序同时监听键盘（包含远控注入）、原始键盘、所有已连接 HID 集合及媒体命令，显示匹配事件、未知事件和该时段未见事件，并将结果写入 `%TEMP%\T1Vibe-key-check-*.txt`。只有在提示时确实按过键才能比较结果；未知事件不会被自动算作语音信号，普通键盘同样可能产生匹配键码。测试期间避免使用其他键盘，结束或停止后即解除监听。

验证窗口底部会显示所属桌面，应为 `Default`。运行在自动化隔离桌面中的采集无法证明实际远程桌面是否收到按键；监听失败或不在交互桌面时，程序会标记结果不完整。新版将 F9 标为语音转发信号，编码为 `vk=0x78`，需结合本轮实际按键判断来源。

自动测试覆盖语音按下/松开及长按去重、报告 ID 和设备状态隔离、旧报告兼容及长度校验、UU 前台限制、转发按下/松开配对、F9 接收去重与焦点切换、发送失败重试、菜单键过滤、项目新建按钮名称匹配、三个发布程序的内嵌模块加载及原生钩子注册和卸载。焦点、真实按键、UU 转发及滚动仍需人工验证：

1. 从其他窗口聚焦输入框，短按语音键测试听写；长按应只切换一次，松开后再次短按应能切换，再测试回车发送。
2. 主页进入侧栏，测试当前项定位、上下移动、会话打开和项目新建聊天。
3. 应用图标键进入长对话浏览，测试上下滚动；返回键回到输入框。
4. 用鼠标在输入框、侧栏、对话间切换，验证上下与 OK 跟随实际焦点；对话区 OK 只回输入框。
5. 切到浏览器，确认返回、Home、Apps 恢复原始行为；在 UU 内对远端重复以上检查。退出后确认默认按键行为恢复。

## 隐私和系统影响

正常运行不写日志，不保存按键、会话标题或录音，不自行上传内容；显式开启的语音键诊断模式会记录 HID 报告及键盘虚拟键值。Windows 听写使用 Windows 自身的语音服务。

不写注册表，不安装服务或驱动，不添加开机启动。运行时将内嵌钩子释放并校验到 `%TEMP%\T1Vibe\<hash>\HomeHook.dll`；退出会卸载钩子。DLL 可能因其他进程暂时持有而留在临时目录，重启后可清理。

ChatGPT 在前台时，普通键盘的菜单键、浏览器主页/返回键、上下和回车同样参与导航处理；其他应用中保持原始行为。语音键全局映射 Win+H。退出后恢复。

## 目录

- `src/`：主程序和原生 Shell 钩子。
- `tests/`：回归测试。
- `build.ps1`：构建、测试和打包入口。

构建产物和下载的 Zig 由 `.gitignore` 排除；Zig 下载逻辑位于 `build.ps1`。发布程序可将 `dist/` 中的 EXE 上传至 GitHub Releases。项目未指定开源许可证。

Zig 仅在从源码构建时需要，运行打包后的 EXE 不需要 Zig、Visual Studio 或其他开发工具。
