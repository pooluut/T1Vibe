# UU 直接传递 Win+H 实验

2026-11-07 用户实测：本地记事本正确弹出听写，触发次数为 1；远端记事本正确弹出听写，远端触发次数为 0。结果支持当前 UU 配置可传递操作端转换出的 Win+H，远端无需再次转换原始语音键。

本实验验证操作端的语音键转换为 Win+H 后，UU 是否会将组合键送到远端。程序不使用 F9，不改变输入焦点，不接管导航键。实验模式不代表完整功能已实现。

1. 将 `dist/win-h-experiment` 文件夹复制到两台电脑。
2. 在两端从托盘退出旧 T1Vibe（包括转发端与接收端），然后双击文件夹中的 `Start-DirectVoiceExperiment.cmd`。两端使用相同文件。
3. 先在操作端记事本的文本输入区按语音键，确认本机能出现 Windows 听写面板。再次按语音键结束听写。
4. 在远端打开记事本并点击输入区，将操作端的 UU 远程画面置于前台，再短按遥控器语音键。
5. 观察听写面板出现在哪台电脑，以及文字输入到哪一端。可在远端手工按 Win+H 作对照，确认远端系统听写本身正常。
6. 记录结果：仅本机出现、仅远端出现、两端都出现、两端都没出现；同时记录操作端状态窗口的触发次数、完整提交次数及最近前台进程。

实验窗口可最小化到托盘，双击托盘图标查看状态。查看状态会改变前台窗口，应在完成一次按键后查看，下一轮先重新聚焦 UU。状态中的“完整提交”只表示操作端 Windows 接受了四个键盘事件，不能证明远端收到。

远端实例只在收到原始语音信号时做转换，不会再次转换已收到的 Win+H。若原始语音键确实无法经 UU 传递，远端这次出现听写面板才是组合键通过的证据。普通软件构建与自动测试无法代替真实 UU 连接上的此项验证。

退出实验时右键两端托盘图标选择“退出”，再按需要启动原有版本。
