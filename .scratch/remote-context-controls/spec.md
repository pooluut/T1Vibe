# 按前台窗口切换的遥控操作

当前阶段：用户已确认设计并授权实现；统一程序已实现，真实 UU 导航与界面焦点待设备验收。

## 已确认需求

- 操作端和远端安装同一版本 T1Vibe。
- 操作端前台为 UU 远程画面时，操作作用到 UU 所连接的目标端；离开 UU 后恢复操作本机。
- T1Vibe 不负责唤出 ChatGPT。用户手工切换到 ChatGPT。
- 返回、App、Home 仅在目标端 ChatGPT 为前台时具有特殊功能；其他时候保持原始按键行为。
- ChatGPT 为前台时：返回聚焦输入区；App 聚焦对话浏览区，上下键用于滚动；Home 聚焦左侧栏。
- OK 在输入区发送消息，在左侧栏打开会话或在项目中新建聊天，在对话浏览区回到输入区且不发送。
- 左、右、电源键保留原有行为。
- 谷歌语音键用于触发 Windows 系统听写（Win+H）。语音来源与音频链路沿用用户已验证可用的配置，不属于本次改动范围。
- 语音键在所有应用中直接触发 Win+H，不主动改变焦点。
- 上下与 OK 跟随实际聚焦区域；鼠标点击输入区后 OK 发送，点击侧栏后按侧栏规则处理。切到其他应用时停止特殊处理。

## 当前实验

- 用户要求先验证：操作端直接将语音键转换为 Win+H，UU 能否把该组合键传给远端 Windows。
- 实验入口为 `T1Vibe.exe --voice-direct-experiment`，两端可运行同一版本与模式；不使用 F9 接收映射，不接管导航键。
- 两端安装程序本身不能证明 UU 会转发组合键；需要实际操作观察远端是否出现听写面板。
- 正式版自动切换及导航规则待实验结果后实现。

## 用户实测结果（2026-11-07）

- 本地记事本中按语音键，系统听写正确弹出，本机实验触发次数为 1。
- 远端记事本中按语音键，远端系统听写正确弹出，远端实验触发次数为 0。
- 结果支持当前 UU 配置可传递操作端合成的 Win+H；远端无需再次接收原始语音键并转换。远端触发次数为 0 不表示失败。
- 正式版语音方案采用操作端全局语音键直接映射 Win+H，不改变焦点，不依赖 F9 转发与接收模式。
- 此结果限于用户此次 UU 连接及配置，不代表所有 UU 配置均已验证。

## 已核查的现有约束

- 当前程序有直连、语音转发、UU 接收三种互斥启动模式，未实现自动切换。
- 已有语音转 F9 的转发实现；真实 UU 是否传递软件生成的 F9 仍需设备验证。
- 部分现有按键处理排除软件注入事件，需在实现时处理 UU 传入按键。
- 按键转发成功与系统听写的音频输入可用是两个独立条件；用户已确认音频可用。
